# 실제 연결·배포 순서

## 1. Supabase

현재 `js/config.js`의 공개 프로젝트 설정과 같은 프로젝트를 사용합니다. 프로젝트를 바꾸면 `.env`와 이 파일을 함께 바꾸세요.

- 새 프로젝트는 SQL Editor에서 001 → 002 → 003 → 004 → 005 → 006 순서로 실행합니다.
- 기존 프로젝트는 마지막으로 적용한 번호 다음부터 실행합니다. 이미 005까지 적용했다면 `006_owner_profile_edit.sql`만 실행합니다. 001 재실행은 기존 테이블과 충돌합니다.
- Supabase Authentication에서 최초 운영자 계정을 생성하고 UUID를 확인합니다.
- SQL Editor에서 아래 UUID를 실제 운영자 UUID로 바꿔 실행합니다. 다른 사람 UUID를 사용하지 마세요.

```sql
insert into public.members(id, display_name, status, adult_confirmed_at)
values ('운영자-Auth-UUID', '첫 주선자', 'active', now())
on conflict (id) do nothing;
```

운영자 계정으로 로그인해 맺어주기 탭에서 초대를 발급합니다. 지인의 프로필은 가입 전후 모두 등록할 수 있습니다. 003 적용 후에는 가입을 마친 지인도 연결 목록에 표시됩니다. 004 적용 후에는 최대 10자 메모를 저장하고 가입·프로필 연결 전의 초대를 삭제할 수 있습니다. 운영자에게 소개받는 역할도 필요하다면 기존 데이터의 소유자 연결은 관리자가 별도 처리해야 합니다.

005 적용 시 `profile-photos` 비공개 Storage 버킷이 함께 생성됩니다. 사진은 JPG/PNG/WebP 원본을 선택하면 긴 변 1600px, 약 1.5MB 이하의 WebP로 자동 최적화되며 프로필당 최대 3장입니다. 새 사진을 추가하거나 삭제하면 기존 공개 승인이 해제됩니다.

006 적용 시 당사자가 자신의 프로필 내용과 사진을 직접 수정할 수 있습니다. 수정 후에는 공개 승인이 해제되어 다시 확인하고 승인해야 합니다.

## 2. 비밀 설정

`.env.example`을 `.env`로 복사하고 서버 변수 4개를 입력합니다. Vercel에도 같은 이름으로 등록합니다. 서버 키를 `js/config.js`에 넣으면 안 됩니다. 설정을 채운 뒤 서버를 재시작합니다.

`GEMINI_API_KEY`는 Google AI Studio에서 새 인증용 키를 발급해 입력합니다. `GEMINI_MODEL`에는 계정에서 사용할 수 있는 안정 버전의 텍스트 모델을 입력합니다. 짧은 소개글에는 `gemini-3.5-flash-lite`를 예시로 사용하며, AI Studio에 표시되는 사용 가능 모델이 다르면 그 ID로 바꿉니다.

## 3. GitHub와 Vercel

변경 코드를 검토해 커밋·푸시합니다. Vercel 프로젝트를 저장소와 연결하고 FastAPI 설정으로 배포합니다. 환경 변수 4개 등록 후 배포를 실행하세요. Vercel은 표준 진입점 `api/index.py`의 `app`을 자동 감지하며 `vercel.json`은 최대 실행 시간 및 불필요한 파일 제외를 설정합니다.

과거 저장소의 추적된 Linux `.venv`는 사용하지 않습니다. 배포에서는 `.vercelignore`와 excludeFiles로 제외합니다. Git에서도 추적을 정리하되 실제 로컬 환경 디렉터리를 삭제할 필요는 없습니다.

## 문제 확인

| 현상 | 확인할 곳 |
|---|---|
| 로그인은 되지만 활성 회원 안내 | Auth UUID와 members.id가 같은지, status=active인지 |
| 회원 데이터를 처리하지 못함 | 002 적용 여부, 서버 service_role 키, Vercel 함수 로그 |
| 초대 가입 후 내 프로필 없음 | 003 적용 후 주선자가 가입한 지인을 선택해 프로필을 저장했는지 |
| 초대 메모·삭제가 동작하지 않음 | 004 적용 여부, 삭제 대상이 가입 또는 프로필에 사용되지 않았는지 |
| 새 프로필 필드·사진 저장이 동작하지 않음 | 005 적용 여부, Storage의 `profile-photos` 버킷 생성 여부, 파일 형식·원본 15MB 제한 |
| AI 준비 중 | GEMINI_API_KEY와 GEMINI_MODEL 등록 및 재배포 여부 |
| AI 한도 안내 | 회원별 10회/15초 제한, Gemini 예산·쿼터 |
| 404 또는 API 대신 HTML | Vercel 프레임워크/루트/진입점 설정 |
| 코드 수정 후 화면 그대로 | 최신 Git 커밋 배포 여부, 브라우저 새로고침 |

가입 도중 DB 응답이 끊기면 Auth 생성 여부와 members/초대 상태를 대조합니다. 로그의 `Signup reconciliation required` UUID로 확인하세요. 이미 정상 회원으로 연결된 Auth 계정은 삭제하면 안 됩니다. 미연결 Auth 계정만 확인 후 정리하고 재가입합니다.

키 유출 시 제공자에서 키를 폐기·재발급하고 배포 변수를 바꿔 재배포합니다. 커밋에 포함됐다면 새 커밋에서 지우는 것만으로 부족하므로 Git 이력 정리와 협업자 재동기화가 필요합니다.
